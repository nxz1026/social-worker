# 社工文档系统架构设计 v2（多用户 + 公网 API）

## 目标

1. 其他 PC / Agent 通过**公网 IP + 自签 HTTPS** 访问，不直连服务器与数据库
2. **多用户多权限**：后台建号，增删改查 + 项目隔离（huadu / huimin）
3. 四入口统一：本机 DSH / 飞书 / API / Obsidian
4. 可重复工作**代码化**，LLM 只做语义判断与文书生成

## 1. 用户与权限（PG 独立库）

独立 database `socialwork`，独立账号 `sw_app`，与 emotion-core 的库完全隔离。

```sql
CREATE DATABASE socialwork;
CREATE USER sw_app WITH PASSWORD '<强密码>';
\c socialwork

CREATE TABLE users(
  id serial PRIMARY KEY,
  username text UNIQUE NOT NULL,
  password_hash text NOT NULL,          -- bcrypt
  role text NOT NULL CHECK (role IN ('admin','editor','viewer')),
  enabled boolean DEFAULT true,
  created_at timestamptz DEFAULT now()
);
CREATE TABLE user_projects(
  user_id int REFERENCES users(id) ON DELETE CASCADE,
  project text NOT NULL,                -- huadu / huimin
  PRIMARY KEY(user_id, project)
);
CREATE TABLE sessions(
  id serial PRIMARY KEY,
  user_id int REFERENCES users(id) ON DELETE CASCADE,
  token text UNIQUE NOT NULL,
  expires_at timestamptz NOT NULL,
  ip text, ua text,
  created_at timestamptz DEFAULT now()
);
CREATE TABLE audit_log(
  id bigserial PRIMARY KEY,
  user_id int,
  action text NOT NULL,                 -- create/update/delete/login/search
  project text,
  target text,
  detail jsonb,
  ip text,
  ts timestamptz DEFAULT now()
);
```

**权限矩阵**：

| 角色 | 查 | 增 | 改 | 删 | 项目范围 |
|---|---|---|---|---|---|
| admin | ✓ | ✓ | ✓ | ✓ | 全部 |
| editor | ✓ | ✓ | ✓ | ✓ | 被授权项目 |
| viewer | ✓ | ✗ | ✗ | ✗ | 被授权项目 |

**每个请求过三道**：认证（session→user）→ 授权（role + `user_projects` 覆盖）→ 审计（写操作落 `audit_log`）。

## 2. 分层与四入口

服务是唯一写入仲裁；存储层（vault / Cognee / PG）不对外直连。

| 入口 | 认证 | 权限来源 | 能做什么 |
|---|---|---|---|
| A 本机 DSH | 本机 ubuntu | admin | 全部（调 API 或脚本） |
| B 飞书 | 飞书账号 | **只分类**（文件夹权限） | 扔文件→分类→归档；不能登录、不能查删改 |
| C 公网 Web/API | **登录 session** | RBAC（users 表） | 按角色 + 项目增删改查 |
| D Obsidian | 本机 ubuntu | admin | 改/删 vault → reconcile 传播 |

**飞书不做 API**：外部用户只进「未分类」文件夹，飞书权限即权限；scan-inbox 作为服务内部 job 统一写入。

## 3. skill vs 代码

| 归属 | 内容 |
|---|---|
| **代码**（服务/脚本） | 归档（拉取/转换/规则分类/落盘/台账）、对账（reconcile）、检索、审计/通知/兜底、**用户/权限/认证/幂等（新）** |
| **LLM** | 分类的语义判断（规则判不了时）、图片主题词、**文书生成（路由/写作/复核）** |

skill 只保留「路由 + 检索 + 写作 + 复核」，**改调 API**，不再直接跑脚本 → A 入口也走 API。

## 5. API 契约

```
POST /api/login                    {username,password} → {token}
GET  /api/me                       → {user, role, projects}
GET  /api/docs?project=&category=&q=&page=   → 列表（按项目过滤）
GET  /api/docs/{id}                → 内容
POST /api/docs                     {file, project?, category?} → 归档
PATCH /api/docs/{id}               {content} → 修改
DELETE /api/docs/{id}              → 删除（md+原件+索引+台账）
GET  /api/search?q=&project=       → Cognee 检索
POST /api/generate                 {type, context} → 文书生成（LLM）
GET  /api/admin/users              → 用户列表（admin）
POST /api/admin/users              → 建号（admin，不开放注册）
PATCH /api/admin/users/{id}        → 改角色/项目/禁用（admin）
GET  /api/admin/audit              → 审计（admin）
```

## 6. 删除与对账（已有代码，需部署/扩展）

## 7. 部署（自签证书 + nginx）

```bash
# 自签证书（10 年）
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout /etc/nginx/ssl/sw.key -out /etc/nginx/ssl/sw.crt \
  -days 3650 -subj "/CN=<公网IP>"
```

nginx server（443）：

```nginx
server {
    listen 443 ssl;
    server_name <公网IP>;
    ssl_certificate     /etc/nginx/ssl/sw.crt;
    ssl_certificate_key /etc/nginx/ssl/sw.key;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 100M;      # 上传原件
    }
}
```

FastAPI 服务：systemd user service，监听 127.0.0.1:8000。

**踩坑（重要）**

7. **`convert-md.py --force` 是危险操作**：会重转所有 md 并**丢失头部**（`> 原件：...` 是 scan-inbox 加的，convert-md 不加）。本次为恢复误改的文档用了 `--force`，导致 huimin 3 个 md 头部丢失，其中一个靠台账 `feishu_token` 手动补回；另外 2 个公众号推文无台账记录（手工维护），头部无法恢复。
   - 教训：**改真实文档前先备份**；`--force` 只用于确实要全量重转的场景。
