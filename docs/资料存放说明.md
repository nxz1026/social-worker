# 社工资料存放说明

一句话：**原始文件放飞书「未分类」，剩下的服务器自动做；要手工放服务器就丢 `sources/projects/<项目>/`。**

## 一、飞书端

根目录「社工知识库」（[打开](https://<tenant>.feishu.cn/drive/folder/<root-token>)）

```
社工知识库/
├── 未分类/          ← 你只需要往这里放
└── 已分类/          ← 服务器自动归档，别手动放
    ├── 花都/  {发票票据, 项目计划, 项目执行, 日常工作佐证, 政策文件, 其他}
    ├── 惠民/  {同上 6 类}
    └── 共享/  {同上 6 类}
```

| 你想干什么 | 放哪里 |
|---|---|
| 手机/电脑传文件 | 飞书「未分类」 |
| 直接发图片给机器人 | 私聊 Mimir（飞书应用 `cli_a94b821458f81cc6`） |
| 找已经归档的文件 | 飞书「已分类/<项目>/<类别>/」 |

- 服务器每 **15 分钟**扫一次「未分类」，处理后自动移到「已分类」
- 「已分类」是归档视图，**不要手动往里放**（不会被索引）
- 另一个入口：直接私聊机器人 Mimir，发文件/图片，或者说一句「这个归花都」

## 二、服务器端（`/srv/social-work/`）

```
/srv/social-work/
├── sources/                    原始文件存档（只存档，不进知识库）
│   ├── projects/huadu/<类别>/
│   ├── projects/huimin/<类别>/
│   ├── projects/shared/<类别>/
│   └── _待确认/<类别>/          文件名读不出日期和单位的手写资料（保留原名，等人工）
├── vault-huadu/                花都 Obsidian 仓库（md 在这里）
│   ├── 使用说明.md
│   ├── md/<类别>/<文档名>/<文档名>.md + media/
│   └── media/<类别>/           日常工作佐证照片原件（配套「档案条目」md 在 md/<类别>/）
├── vault-huimin/               惠民 Obsidian 仓库（同上）
├── inbox/                      从飞书拉下来的临时区（处理完即清空）
├── state/manifest.yaml         处理台账（幂等，别手改）
├── scripts/                    convert-md.py / scan-inbox.py
├── feishu-flow.yaml            飞书目录 + 项目/类别配置
└── docker-compose.yml          Cognee + Syncthing
```

| 文件类型 | 服务器位置 | 进知识库吗 |
|---|---|---|
| docx / xlsx / pptx / pdf | `sources/projects/<项目>/<类别>/` | 否（转成 md 才进） |
| 转出来的 md | `vault-<项目>/md/<类别>/<文档名>/<文档名>.md` | **是** |
| 日常工作佐证照片 | `vault-<项目>/media/日常工作佐证/<日期>-<单位>-<内容关键词>.jpg` | 图片本身否；配套「档案条目」md 进库（M10） |

|---|---|---|

## 四、数据流

```
飞书「未分类」  ──┐
                ├─→ 服务器 inbox/ ─→ 分类（规则层，判不了才 LLM）─→ 转 md ─→ Cognee ─→ Obsidian
私聊机器人      ──┘                                              ↑
DSH 里发文件 → archive.py ───────────────────────────────────────┘
```

- 转换：docx → pandoc；xlsx/pptx/pdf → docling（容器内）
- 归档：原件回飞书「已分类/<项目>/<类别>/」，md 顶部带原件链接（本地文件由 `scan-inbox.py` 补传一份）
- **日常工作佐证照片（手写登记表同理，M10）**：图片本身只归档，不 OCR、不调视觉模型。
  - 命名 `<日期>-<单位>-<内容关键词>.<ext>`：日期优先取**文件名**里的（`2026年11月5日`／`2026-11-05`／
    `20261105`／14 位手机时间戳都认），其次 EXIF 拍摄时间，最后才是文件落盘时间；单位取文件名里的项目关键词。
  - 同时产一条**「档案条目」md**（`vault-<项目>/md/<类别>/<文件名>.md`），只写日期、单位、类别、原文件名、
    **源文件路径**、内容关键词，并注明「手写资料，未做 OCR」。进 Cognee 的是这条条目 —— 手写资料也能按
    「哪天 / 哪个社区」搜到，再顺 md 里的路径回原件。
  - 文件名里**日期和单位都读不出** → 落 `sources/_待确认/<类别>/`，保留原文件名、不编造日期，
    当晚 22:00 的飞书归档汇总里列出来（原因写「文件名无日期/单位」），人工归位后重跑一次。
- 检索：DSH 网页里直接问，或 `python3 /srv/social-work/scripts/cognee.py search "<问题>"`

## 五、客户端（Obsidian）

- 服务器 `vault-huadu/` 和 `vault-huimin/` 通过 Syncthing 双向同步到你的电脑
- Obsidian 里直接打开这两个文件夹就是仓库
- **在 Obsidian 里改文件 = 改服务器上的文件**（双向）
- 服务器地址 `<服务器IP>`，同步端口 `22000`

## 六、常见问题

| 问题 | 原因 / 处理 |
|---|---|
| 飞书放了文件，多久能在知识库搜到 | 15 分钟内（定时扫描） |
| 手写登记表 / 照片搜不到 | 图片不做 OCR（M10）。检索走「档案条目」md 里的日期 + 单位；文件名里两样都没有的会落 `sources/_待确认/<类别>/`，22:00 汇总提醒，人工归位后重跑 |
| 服务器 `sources/` 里的文件搜不到 | 没转 md，跑 `python3 /srv/social-work/scripts/convert-md.py --project <huadu\|huimin\|shared>` |
| md 改了但知识库没更新 | md 改动不会自动重建索引，需在 DSH 里说一声重建 |
| 想加新项目 | 在飞书「已分类」下建项目文件夹，并在 `feishu-flow.yaml` 里加配置 |
| 误删了文件 | Syncthing 版本控制保留 30 天（`.stversions/`）；Cognee 不保留旧副本 |
