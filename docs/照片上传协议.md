# 活动照片上传协议

> 面向调用方（客户端 Agent、人手工上传、批量脚本）。本文是**约定**，服务端按此实现。
> 版本 1.0 ｜ 2026-11-20

## 1. 要解决什么

活动现场拍几十上百张照片，事后归到哪个活动靠猜：
- 微信/飞书下载后 **EXIF 被剥离**，没有拍摄时间
- 文件名不可控（`IMG_0001.jpg`、`微信图片_20261110131250.jpg` 或任意）
- 照片里有场景、人、物，**OCR 读不出归属**
- 每张调 LLM 判断太贵

**结论：归属信息必须在上传时由人指定，不能事后从图片里猜。**

## 2. 核心约定

**一次上传 = 一个批次 = 归属一个活动。**

上传时必须由调用方提供：

| 字段 | 必填 | 说明 |
|---|---|---|
| `project` | ✅ | 项目名，如 `惠民社区保障资金项目` |
| `activity` | ✅ | 活动目录名，如 `11-共治行动-第一期` |
| `shot_date` | 建议 | 拍摄日期 `YYYY-MM-DD`，不给则取上传当天 |
| `scene` | 可选 | 场景说明，如「主会场」「分组走访」 |
| `note` | 可选 | 批次备注 |
| `compress` | 可选 | 是否压缩，默认 `true` |

**服务端据此确定归属，不再对单张图片做识别。**

## 3. 三种上传方式

### 3.1 方式 A：多文件直接上传（推荐，最常用）

```
POST /api/sw/photos/upload
Content-Type: multipart/form-data
Authorization: Bearer sk-sw-xxx

project=惠民社区保障资金项目
activity=11-共治行动-第一期
shot_date=2026-11-10
scene=主会场
files=@a.jpg
files=@b.jpg
files=@c.jpg          ← 同名字段重复 N 次
```

**限制**：
- 单请求最多 **200 张**
- 单张上限 **50 MB**（原图）
- 总量上限 **500 MB/请求**（超了就分包）

**返回**：

```json
{
  "ok": true,
  "batch_id": "20261120-143025-11-共治行动-第一期",
  "activity": "11-共治行动-第一期",
  "received": 65,
  "saved": 65,
  "skipped": [],
  "compressed": 65,
  "paths": ["11-活动照片资料/20261110_143025_001.jpg", "..."],
  "total_bytes": 314572800
}
```

**文件重命名规则**（服务端自动，调用方无需管原名）：

```
{shot_date}_{批次内序号:03d}.jpg
例：20261110_001.jpg  ~  20261110_065.jpg
```

原名记录在 `_photos.json` 里，随时可查来源。

### 3.2 方式 B：压缩包上传（跨活动整理时用）

一次传了多个活动的照片时，打成 zip 上传，**目录名即归属**：

```
现场照片.zip
├── 11-共治行动-第一期/
│   ├── IMG_0001.jpg
│   └── IMG_0002.jpg
└── 14-志愿服务-第一期/
    └── IMG_0003.jpg
```

```
POST /api/sw/photos/upload-archive
Content-Type: multipart/form-data

project=惠民社区保障资金项目
archive=@现场照片.zip
shot_date=2026-11-10
```

**规则**：
- 压缩包内**一级目录名必须是活动目录名**（或它的前缀，如 `11-` 也能匹配）
- 无法匹配的活动目录 → 整目录跳过，列进 `unmatched`
- 支持 `.zip`，`.7z`/`.rar` 需客户端先解压

**返回**：

```json
{
  "ok": true,
  "matched": {"11-共治行动-第一期": 42, "14-志愿服务-第一期": 30},
  "unmatched": {"其他照片": 8},
  "total_saved": 72
}
```

### 3.3 方式 C：按修改时间自动归组（兜底）

压缩包里没有目录结构、只有一个活动时：

```
POST /api/sw/photos/upload
project=...
activity=11-共治行动-第一期   ← 仍然必填
files=@*.jpg
```

**此时 `activity` 是唯一归属依据**，不需要其他判断。

## 4. 压缩与存档

**原件与压缩版分离存放**：

```
11-活动照片资料/           ← 原件（JPEG 质量 95，最大边 2560px）
精选/                      ← 简报用图（6~8 张，1600px）
_照片索引.jpg              ← 九宫格拼图，进 Obsidian
_photos.json              ← 批次元数据
```

| 处理 | 规格 | 用途 |
|---|---|---|
| 原件压缩 | 最大边 2560px，JPEG q=95 | 存档，约 1/4 体积 |
| 精选 | 最大边 1600px | 做资料、写图注 |
| 索引拼图 | 3×2 网格，1200px 宽 | Obsidian 预览 |
| 原图 | **不保留**（除非 `compress=false`） | — |

**为什么要压原件**：130 张原图占 650MB，压到 2560px 后约 160MB，画质在屏幕上无差别。

## 5. 元数据文件 `_photos.json`

每个活动目录一份，记录每张照片的来源：

```json
{
  "batches": [
    {
      "batch_id": "20261120-143025",
      "shot_date": "2026-11-10",
      "scene": "主会场",
      "note": "活动结束后一口气传的",
      "uploaded_by": "聂聃",
      "uploaded_at": "2026-11-20T14:30:25+08:00",
      "count": 65
    }
  ],
  "photos": [
    {"name": "20261110_001.jpg", "original": "微信图片_20261110131250_157_11.jpg",
     "size": 812345, "batch": "20261120-143025"}
  ]
}
```

**这个文件不同步到 Obsidian/飞书**（`.stignore` 已排除 `activity.yaml`，需加 `_photos.json`）。

## 6. 与现有约定冲突的处理

**现有规律**：活动目录内文件必须是 `NN-名称.docx` 格式，图片需过 `check_api_upload_name`。

**照片目录例外**：`11-活动照片资料/`、`10-物资照片资料/`、`12-发票/` 下的文件**不走 NN- 规则**，用本协议的日期序号规则。

服务端已在 `_activity_upload_filename` 里对这几个目录放行，新端点沿用。

## 7. Cognee 入库

**不存单张照片节点**，只存“活动有照片”这条事实：

```json
{
  "活动": "共治行动（第一期）",
  "项目编号": "CDYJR2026008-C-1110002",
  "照片数": 65,
  "拍摄日期": "2026-11-10",
  "场景": ["主会场", "分组走访"],
  "精选图注": ["图1 社工讲解公约", "图2 居民清理通道"]
}
```

检索「共治行动有哪些现场照片」能命中，不污染图谱。

## 8. 防重复（必读）

微信/飞书下载会把图改名（`IMG_0001.jpg` → `微信图片_xxx.jpg`），**只比文件名挡不住重复**。
三层校验，缺一不可：

### 8.1 三层校验

| 层 | 依据 | 挡什么 | 结果 |
|---|---|---|---|
| L1 文件级 | 目标路径同名文件已存在 | 同一批重复提交 | `skipped` 里列出 |
| **L2 内容级** | **sha256 与已有照片相同** | **改名后重传同一张** | `skipped` 里列出并标注原文件名 |
| L3 批次级 | 同活动 + 同 `shot_date` + 同 `scene`，24 小时内已成功上传过 | 整批误提交 | 返回 409 `DUPLICATE_BATCH`，带上次批次 id |

**L2 是主防线**。服务端对每张图算 sha256，与 `_photos.json` 里已记录的哈希表比对。

### 8.2 服务端不拦截、只报告的情况

- 同一活动传两张**内容相同但确属不同用途**的照片 → 仍算重复，需调用方改名或加 `allow_duplicate=true`
- 强制上传：`allow_duplicate=true` 时跳过 L2/L3，只保留 L1

### 8.3 `_photos.json` 里的哈希表

```json
{
  "hashes": {
    "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08": "20261110_001.jpg"
  }
}
```

**只存 64 位十六进制，不存原图**，一个活动 200 张也就 13KB。

### 8.4 Web 界面的预检

选中文件后**先算哈希再上传**：

```
选中 65 张 → 计算 sha256（浏览器 Web Crypto，约 2 秒）
           → 调 POST /api/sw/photos/precheck 比对
           → 返回 {"new": 62, "duplicated": 3}
           → 界面显示「3 张已在库中，将跳过」
           → 用户确认后才真正上传
```

**避免用户传完 500MB 才发现全是重复。**

## 9. 错误码

| code | HTTP | 说明 |
|---|---|---|
| `ACTIVITY_NOT_FOUND` | 404 | 活动目录不存在 |
| `TOO_MANY_FILES` | 400 | 单请求超 200 张 |
| `FILE_TOO_LARGE` | 413 | 单张超 50 MB |
| `NOT_AN_IMAGE` | 400 | 扩展名不是图片 |
| `ARCHIVE_UNSUPPORTED` | 400 | 压缩格式不支持（只收 zip） |
| `ARCHIVE_EMPTY` | 400 | 压缩包里没有图片 |
| `NO_MATCHED_ACTIVITY` | 400 | 压缩包内目录都匹配不上活动 |
| `READONLY` | 403 | 该项目只读 |
| `DUPLICATE_BATCH` | 409 | 同活动+同日期+同场景 24 小时内已传过（`allow_duplicate=true` 可绕过） |

## 10. 调用示例

### 9.1 客户端 Agent（批量传 65 张）

```bash
curl -X POST https://<host>/sw-api/api/sw/photos/upload \
  -H "Authorization: Bearer sk-sw-xxx" \
  -F "project=惠民社区保障资金项目" \
  -F "activity=11-共治行动-第一期" \
  -F "shot_date=2026-11-10" \
  -F "scene=主会场" \
  -F "files=@IMG_0001.jpg" \
  -F "files=@IMG_0002.jpg" \
  $(for f in IMG_00*.jpg; do echo -F "files=@$f"; done)
```

### 9.2 压缩包

```bash
zip -r 现场照片.zip 11-共治行动-第一期/ 14-志愿服务-第一期/

curl -X POST https://<host>/sw-api/api/sw/photos/upload-archive \
  -H "Authorization: Bearer sk-sw-xxx" \
  -F "project=惠民社区保障资金项目" \
  -F "shot_date=2026-11-10" \
  -F "archive=@现场照片.zip"
```

### 10.3 Web 界面

活动详情页 → 「上传照片」按钮 → 弹窗：

| 字段 | 控件 | 校验 |
|---|---|---|
| 项目 | 下拉 | 必填，只列有写权限的项目 |
| 活动 | 下拉（随项目联动） | 必填 |
| 拍摄日期 | date 选择器 | 必填，不得晚于今天 |
| 场景 | 文本框 | 可选，如「主会场」 |
| 照片 | 拖拽区 / 选择文件 | 必填，实时显示「已选 N 张 / X MB」 |

**流程**：选文件 → 浏览器算哈希 → 调 `/precheck` → 显示「新增 62 / 重复 3」 → 用户确认 → 上传 → 回执列出跳过的具体文件名。

### 10.4 预检端点

```
POST /api/sw/photos/precheck
{
  "project": "...", "activity": "...",
  "hashes": ["9f86d0...", "3c59dc..."]
}
→ {"new": 62, "duplicated": ["9f86d0...", "3c59dc..."], "duplicated_files": ["IMG_001.jpg", ...]}
```

只比对哈希，不落盘，不占带宽。

## 11. 对调用方的约束

**必须遵守**：

1. **一次上传只对应一个活动**（方式 A/C）；跨活动用压缩包（方式 B）
2. **不要在文件名上动心思**——服务端会重命名，原名只做记录
3. **不要依赖 EXIF**——微信/飞书已剥离，服务端不读 EXIF

**可选优化**：

- 传 `shot_date` 能让文件名带正确日期，不传就用当天
- 传 `scene` 能在 `_photos.json` 里留场景信息，对后续图注有用
